GAME NIGHT

UI/UX review + improvement suggestions

Source: live code audit
Scope: Home · Game room · Nav · Catalog · Theming

The app has a strong, coherent retro identity and unusually careful mobile ergonomics — large touch targets, safe-area handling, destructive-action confirmations, and reduced-motion support are all real strengths. The main weaknesses are readability (text too small, a permanent CRT overlay) and visual density (Home stacks many equal-weight CTAs, the catalog is a wall of tiles). The fixes below are additive — none change the game architecture.

01WHAT'S WORKING

CONSISTENT THEME SYSTEM

All color flows through --c-* tokens with per-theme overrides. Adding a theme is a token block, not a component rewrite. Hex-hardcoding is banned. This is the right foundation.

MOBILE ERGONOMICS

44px touch targets, safe-area insets, iOS 16px input floor, tap-highlight suppression, and a blocked-tap toast instead of silent failures. Very few apps handle this layer this deliberately.

HONEST DANGER VOCABULARY

Destructive confirmations (LEAVE MATCH) and danger states use a dedicated red, distinct from Player O's pink and the CTA yellow. The leave-match back-gesture guard is a thoughtful touch.

02FINDINGS

Ten findings, each with evidence from the current code. Tick the ones you want fixed and queue them — I get an item-by-item receipt so nothing is dropped.

ID Severity Area Issue Suggested fix
F-01 HIGH Typography Pixel font is used at 7–10px for functional labels everywhere — tab labels (7px), stat labels (7px), game tags (7px), GameStatus (10px). Press Start 2P at that size is barely legible. Floor body/label text at a readable size; use the pixel font only for short headings and CTAs, mono for secondary copy.
F-02 HIGH Theming CRT scanlines + a heavy edge vignette (rgba(0,0,0,.65)) are always on via body::before/::after. On light themes (paper, matcha) they muddy the page and darken the edges. Make the CRT effect opt-in per theme (or a single toggle), and disable/soften it on light themes. Keep reduced-motion killing it.
F-03 MED Home Home stacks a dozen near-equal sections: invites, daily + join code, HOW IT WORKS, Continue Playing, catalog, Recently Played, solo CTA, playground CTA, stats, upgrade nudge, install CTA, iOS hint. Split into primary (play now) and secondary (discover / playground / stats / settings). Collapse less-used banners behind a single secondary zone.
F-04 MED Catalog 50+ games in the ALL view grouped by 6 categories is a wall, especially at 2 columns on mobile. Search, filters, and favorites help but the default is undifferentiated. Default to a curated "Featured" or "Recent + Favorites" view. Make player count (solo / 2P / 3–8P) a clearer badge on every card.
F-05 MED Game room The room toolbar packs ← HOME, theme, rules, switch, invite, mute, audio settings, a badge, and the game code into one row — ~8 controls before the board on mobile. Keep back / theme / mute / invite visible; move rules, switch, and audio settings into an overflow menu.
F-06 MED Layout Five+ overlay layers can coexist: header, sticky filters, tab bar, round-end action bar, proposal banner, and the real-time "match still running" banner. Offsets are handled but the layer stack is fragile. Consolidate transient banners into a single toast/banner slot with a stable position, and reduce the number of fixed regions per screen.
F-07 LOW Theming 12 themes appear as a flat text list with only three 5px color dots each — the visual difference between themes is not visible before picking. Replace with a grid of larger swatch tiles (name + real palette chips), so each theme previews its actual look.
F-08 LOW Accessibility --c-dim is used for a lot of secondary text. On several themes the dim tone sits near or below the readability threshold for its background. Audit each theme's --c-dim against its surface and bump the ones that fall short; keep the token-based approach.
F-09 LOW Copy Minor inconsistency: join-code placeholder is lowercase "enter code…" while every other label is uppercase; some CTAs use "→" and some use "›". Normalize to the uppercase pixel-voice convention and pick one arrow style.
F-10 LOW Catalog Party games (3–8 players) are only distinguished by a tiny 7px tag. Users can open a party room expecting a 2-player game. Add a visible "3–8P" party badge and set the party category apart in the catalog.
