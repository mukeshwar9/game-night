Game Night monetization, Phase 1 (web)

Branch fm/games-monetization-build-s1, head 1d64132. Not deployed. Paddle sandbox only, placeholder keys, no live charges.

Game Night Pass (.99 a month or .99 a year, the host buys it), cosmetic packs (.99 to .99) and Supporter (.99). Every free game stays free, nothing sold changes who wins, and there are no random paid rewards. Premium themes, the premium font, every pass or pack avatar item and the pixel emote pack all go through one entitlement check.

Bypass proof

1. Local development and emulators

Every premium item is open on a dev server and in emulator mode, never in a production build (bypassActive, unit-tested). localStorage['gn-premium-bypass']='off' turns it off to inspect the locked UI; it can only turn it off.

2. Admin emails, in production

ADMIN_EMAILS lives in the functions config, not the client bundle. syncAdminAccess (callable) checks the verified Google email, or the existing users/{uid}/admin flag, then writes entitlements/{uid}/admin and a premiumAdmin custom claim. Clients cannot write that record (rules tests). Removing an email revokes it on next sign-in.

Also covered end to end (tests/e2e/premium.spec.js): bypass open, locked with bypass off, pack unlocks live, refund re-locks, active Pass unlocks, lapsed Pass locks, admin flag unlocks, locked theme and avatar open the paywall.

Not built, and limits

  • Host perks (room banner, room theme, playlists, bigger rooms) are listed as "coming" on the Pass page; the Pass today unlocks cosmetics, the monthly-drop promise and the star badge data only. The entitlementsPublic badge is written but not yet drawn next to names.
  • Avatar and emote gates are client-side: no database rule yet stops a modified client saving a premium avatar string. Fine for now, worth a rule before packs sell heavily.
  • "Earned" avatar items (play-unlocked) stay open: no earn tracker exists yet.
  • Free week for the Pass is configured on the Paddle price, not in code. Restore Purchases and the phone apps are Phase 2.
  • No live checkout was exercised: it needs the Paddle sandbox account and a deployed function. Webhook, grants, refunds and signatures are covered by unit tests with a fake database.

Captain steps

  1. Create a Paddle account (sandbox first), create prices for every key in PRODUCTS (pass-monthly, pass-yearly, supporter, and one per pack), 7-day trial on both Pass prices, default payment link /shop.
  2. Fill functions/.env from .env.example: PADDLE_PRICES and ADMIN_EMAILS (your verified Google emails).
  3. firebase functions:secrets:set PADDLE_API_KEY and PADDLE_WEBHOOK_SECRET (sandbox values).
  4. Add a Paddle notification destination to the deployed paddleWebhook URL for subscription.*, transaction.completed, adjustment.updated.
  5. Deploy rules, functions and hosting together; test a sandbox purchase, cancel and refund.
  6. Have the Terms and Privacy edits reviewed, then switch PADDLE_ENV=production with live keys only when ready.
