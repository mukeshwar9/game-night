GAME NIGHT · NEW GAME DESIGN · 2026-09-27 · DESIGN ONLY, NOT BUILT

ANIMAL STACK

Take turns dropping animals onto one wobbly tower on a tiny island. Make it topple and you lose a heart. Last player with hearts wins.

1-4 PLAYERSSOLO: BOT + CLIMBSAME DEVICE 2-4PONLINE 2-4P~6-9 MINPORTRAIT FIRST

Based on "Animal Stack" in 2 Player Games: Offline Games (Moreno Maio), itself in the tradition of Doubutsu Tower Battle. The rules are generic; all art, names and sounds here are original pixel art built from Game Night's own theme tokens.

THE SHORT VERSION
  • Physics: vendor planck.js (Box2D port) with its six Math.sin/cos calls swapped for the repo's deterministic Taylor trig (the same one artilleryLogic.js uses). Measured: stock trig differs between V8 and JavaScriptCore and one stock-planck tower diverged; the patched build matched on 42 of 42 test towers.
  • Online: RTDB only, no WebRTC. It uses the Artillery pattern: a seed plus an append-only list of {x, rot} drops, and every client replays. Each drop also writes a hashed checkpoint as a tripwire. It is an nPlayer room for 2-4 players.
  • Cost: the entry bundle stays at 254.3 / 320 KB gzip. On first play the lazy chunk is about 60 KB gzip (planck ≈46 KB). My estimate is ~17 dev-days, in 5 phases.
  • Try it: section 4 is a working prototype running this exact engine.
THE TWELVE ANIMALS

1CORE LOOP, RULES, MATCH

A turn takes about 5-15 seconds: aim, drop, watch it settle. A tower ends when any animal leaves the island. The match is played over several towers.

RULES

  • Pieces: a seeded 12-bag deals the animals, so each animal appears once every 12 drops. Everyone sees the current piece and the NEXT one.
  • Aim: the piece hovers 0.45 m above the tallest point of the tower. You can move it anywhere within ±3.2 m and rotate it in 15° steps (24 orientations).
  • Drop: the piece is released with zero velocity. You cannot nudge, hold or "place" it.
  • Topple: the tower topples the moment any animal's centre falls below 1.2 m under the island top, whoever dropped it. The player whose drop set it off loses a heart.
  • Settled: a drop has settled once every body has been still (|v| < 0.06 m/s, |ω| < 0.1 rad/s) for 36 ticks, or after a 540-tick (9 s) cap.
  • Timer: 15 s to aim when online. When it runs out, the piece auto-drops where it is. The timer is off by default on one device and does not apply in CLIMB.

5PHYSICS STACKING

A stacking game lives or dies on two things. First, contacts between many resting polygons have to be stable. Second, for online play, every phone has to reach the same tower. The repo already has a determinism contract (artilleryLogic.js:1-10: only + − × ÷, Taylor detSin/detCos, fixed timestep, mulberry32). This design keeps that contract.

THE CONTRACT
  • Vendor planck.mjs as src/lib/vendor/planck-det.js. A build script rewrites its Math.sin / Math.cos (3 aliases each) to detSin/detCos, and a test fails if any remain. Math.sqrt is correctly rounded per spec; Math.atan2 is only used in joints and getAngle helpers we don't call.
  • Move detSin/detCos/mulberry32 out of artilleryLogic.js into a shared detMath.js, so both games use the same code.
  • Step at a fixed 1/60 with 8 velocity and 3 position iterations. Settle detection is counted in ticks, never wall time.
  • Canonical state: after each settle, quantise to x/y 1e-4 m and angle 1e-5 rad, zero the velocities, and rebuild the world. Every drop starts from an identical, cache-free state, so any drift cannot build up across turns.
  • Rotation input is an integer 0-23 and x is an integer in centimetres. Neither goes through any float path that differs between devices.

PIECE SET

There are 12 animals, each built from 1-5 convex parts. The mix is 4 heavy "foundations", 4 mid, and 4 light or awkward pieces (long, pointy or leggy). Mass is density × area. Colours come from theme tokens (--c-kam*, structure, cta, win), never from the p1-p4 player colours, so a piece never looks like it belongs to a player.

TOPPLE DETECTION

Every tick, check whether any body's centre has y < −1.2, which means it is off the island and in the water. The island's sides overhang, so nothing can rest partway down. The verdict is decided by the sim, not by the camera. The first tick it happens ends the drop: {fell, fellTick}.

CAMERA

The view is 6.8 m wide. The camera's bottom edge follows max(−2.1, hoverY + 1.4 − viewHeight) with a 0.08 lerp; with reduced motion it snaps instead. The camera holds still while a drop settles. On a topple it follows the fall at 0.5× for about 0.8 s. The ruler and the CLIMB best line pan with the world.

CONTROLS ↔ SIM

Only {x (cm), r (0-23)} leaves the controls. The spawn height comes from the canonical tower (tallest vertex + piece radius + 0.45 m), so every client computes the same drop point. The piece's identity is pieceSequence(seed)[dropIndex] and is never sent.

6ONLINE SYNC

This is the Artillery model (ArtilleryGame.jsx: seed plus an append-only shot list, every client replays) with two additions. Each drop writes a checkpoint, so late joiners get the tower instantly and any drift is caught. The rest reuses the nPlayer seat, turn and away machinery from Chain Reaction 4P.

DATA MODEL (ONE NODE → ONE FIELD_NULLS KEY)
games/{id}
  gameType: 'animalstack'   status   players/{uid}{name,avatar,joinedAt,online}
  stack: {
    round: 2,  seed: 918273645        // new seed per tower (startRound)
    order: [uidA, uidB, uidC]         // seat order at START (joinedAt, uid)
    turn: 1                           // index into order
    hearts: {uidA: 2, uidB: 1, uidC: 2}
    drops: {pushKey: {by, n, x: 35, r: 6, auto?}}   // append-only per tower
    cp: {n: 7, hash: '16f96ae1', poses: 'k,x,y,a;…'} // ≈ 30 B/animal
    phase: 'aim' | 'settle' | 'roundover' | 'over'
    aim: {x, r}                       // ghost, active seat only
    deadline: serverMs                // useServerClock
    result: {toppler, n}              // set on fell
    auto: {uid: missCount}            // away auto-drops
  }
  • Rules (database.rules.json + tests/rules/): only order[turn] may append a drop, with n == count, |x| ≤ 320 and 0 ≤ r ≤ 23. Any seated player may write cp when cp.n + 1 == n. Only the active seat may write aim. Every .validate must accept unchanged data, because party pages run transactions on the whole node (firebase-rules.md).
  • Late join, reload or spectate: read cp.poses and render at once. If the phase is settle, replay just the last drop.
  • Dropper disconnects mid-settle: nothing breaks. Any client can write the checkpoint, and they all compute the same one.
  • Away player: once the deadline passes, the coordinator auto-drops at the last ghost aim (or centre at 0°). Two auto-drops in a row while offline eliminates the player, following CR4's skipAwayTurn.
  • Cheating: a client can only choose x and r, the same as tapping. Poses in cp are checked against every other client's replay. A forged topple verdict would be outvoted by honest clients (v2: a Cloud Function replay verifier, since the sim runs in Node).

RISKS
  • Low-end Android CPU: one tick with about 30 bodies should be fine, but I have not measured it. The bot search costs roughly 20-90 ms per candidate in Node (unwarmed), so it is spread across frames. Mitigation: a Web Worker, and cap the bot's search ticks.
  • Vendored library upkeep: planck updates need the patch script re-run. Pin the version.
  • Hidden non-determinism: for example iterating a Map built in a different order, or a newer planck adding Math.* calls. Mitigations: the guard test, plus a CI job that runs the replay suite under jsc on the macOS runner.
  • Feel tuning (friction, density, spawn height) is subjective. Budget a playtest round.
  • nPlayer gaps: no proposal flow, and leaderboard credit is X/O only. This is known and consistent with CR4.
  • Local mode for a custom page needs a small shared routing change (supportsLocalPlay excludes custom).
