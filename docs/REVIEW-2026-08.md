# Consolidated Review — Game Night, August 2026

A synthesis of thirteen independent reviews of the games platform: four correctness passes (53 findings), five game-design passes, one platform-retention pass, two engine-implementation passes, and four interface-quality passes. Catalog stood at 47 reviewed games/variants (plus 3 shipped-but-unreviewed and one uncommitted-at-review-time game — see §7).

This document sits alongside `UX-IMPROVEMENTS.md` and `MOBILE-UX-AUDIT.md` (both fully implemented, both read and not re-litigated by any of the source reviews) as the next layer down: correctness, game design, engine quality, and the interface gaps those two audits' own scope didn't cover.

**Format:** every finding keeps its source review's file:line pointers, severity, and effort label. Where a design review labelled a number as a starting guess rather than a measured fact (Numbers Policy posture B), that label is preserved here — a number that loses its posture reads as sourced when it isn't. Nothing in this document is a new finding unless explicitly marked in §8.

The full source reports are in `docs/reviews/2026-08/` — every finding below traces back to one of them.

## 1. Executive summary

**Read this section only, and you still know what to do first.**

The platform's shell (catalog, discovery, mobile chrome, social plumbing) is in genuinely good shape — both prior audits closed nearly everything they found. This review looked one layer deeper: does each game actually work, is each game worth playing, and is the engine underneath sound. The honest answer: **mostly yes, with two shipped games broken on the device most players use, one real data-corruption bug, and a retention layer that has been built twice (Daily Challenge, Leaderboard) and works properly neither time.**

**Do these five things first, in order:**

1. **Fix Word Duel on touch.** Every round's word-setting phase has no on-screen keyboard — a phone player is stuck at "PICK A WORD" forever. `WordDuelGame.jsx:495` (missing `<Keyboard>`), ~3 lines. This is the single highest-impact fix in the entire review: Critical severity, Low effort, blocks an entire game on the majority device class.
2. **Fix Space Duel's touch controls** — combat buttons render ~14px tall spanning both thumb zones (`SpaceduelArena.jsx:65,169`). Critical, Medium effort.
3. **Filter the Word Hunt dictionary.** A 125k-word list with no profanity/slur filter is directly playable and displayed to both players (`public/wordhunt-dict.txt`). Broken, Medium effort (a denylist pass, no logic change).
4. **Fix the Mancala pit-corruption bug** before that game ships for real — `normalizePits()` reindexes sparse Firebase reads by array position instead of key, silently misplacing seeds (`mancalaLogic.js:21-24`). Broken, Small effort. (Mancala was uncommitted work at review time in the main checkout — coordinate before merging.)
5. **Decide what to do about the four convergent platform themes in §3** — host latency advantage, the mixed-game leaderboard, the vanished-after-the-match head-to-head data, and color-only signaling. Each was found independently by 2–4 separate reviews. These are the strongest signal in the whole document because nobody was told to look for them twice and found them anyway.

Everything else — the 53 correctness findings, the per-game keep/rework/cut calls, the engine notes, the interface-quality catalog — is real and actionable, but ranked below these five in player impact. The single most valuable non-obvious fact in this review: **the head-to-head data the leaderboard theme complains about not existing already exists, is already unit-tested, and is wired into zero screens** (`profile.js`'s `getHeadToHead()`/`formatHeadToHeadLabel()` — a ~15-line wire-up into `GameStatus.jsx`, not a data-model project).

One gap to know about before reading further: **the input/timing/audio/hooks layer (`src/hooks/`, the sound layer, `src/components/loading/`, `EmoteBar.jsx`) was never reviewed** — the reviewer assigned to it (`ge-input-s1`) was torn down before producing a report. Treat every reflex/timing game's actual feel, and every game's audio/input-latency behavior, as unverified rather than clean. See §7.

## 3. Themes — the strongest signal in the set

These four findings recurred **independently** across reviews that had no visibility into each other's work. Naming which reviews converged, because convergence without coordination is stronger evidence than any single finding.

### Theme 1 — The host has a real, structural latency advantage in most real-time games, and three games already solve it

**Converged in:** correctness (arcade), design (arcade), and both engine reviews (arena, and indirectly the board-engine review's cross-reference).

Pong and Sumo give the guest local prediction of its own actor (re-simulating the same friction/impulse/integrate math client-side, reseeded from each snapshot). Paint does the same for its actor's movement. **Snake, Tron, and Space Duel's fire path do not** — the guest renders purely off host snapshots with no local prediction, so a real-world RTT eats into the guest's own move on a tick-discrete, instant-death grid (Snake/Tron) or against a 0.35s fire cooldown (Space Duel). The design review's verdict: this turns "connection-quality test wearing a skill game's clothes" for the guest seat specifically, on three otherwise well-designed games. The engine review confirms this is a single reusable pattern, not three separate builds — reseed a local predicted-state ref per snapshot, then re-run the same per-actor step function client-side (for Snake/Tron: predict the next 1-2 discrete moves from buffered input rather than dead-reckoning a continuous velocity).

*Fix scope:* one engineering investment (the prediction pattern), applied to 3 call sites. Space Duel's ship-movement half is already solved this way — only its fire path needs the same treatment, a narrower fix than Snake/Tron's full-actor gap.

### Theme 2 — The leaderboard mixes incomparable game types

**Converged in:** correctness (solo), design (solo), platform-retention, and social-layer interface review — four independent reviews, the most of any theme in this document.

`rankEntries` (`leaderboard.js`) sorts by raw lifetime `wins → winrate → games`, summed across every `gameType` a friend pair has ever played, no time window. A Pig win (≈50%-luck, `category: 'dicebluff'`) counts identically to a Chimp Test win (pure skill). There is no per-game or per-period slice, and no way to answer "who's actually good at Mental Math" from this data structure at all — every review that touched it independently called this structurally incapable, not just poorly tuned.

*Converging fix recommendation (design + platform + social reviews all land here):* rank per game (or per category as a coarser first cut) using `users/{uid}/stats.byGame[gameType]`, which is **already written and mirrored, just never read for ranking**; add a rolling time window (7-day, matching the Daily Challenge cadence); for the "parallel-instance" games (Reaction, Typing, Number Memory, Math) rank by personal-best metric instead of win/loss, since two closely-matched players trade wins essentially at random around their true skill there.

### Theme 3 — Nothing persists after a match, and the head-to-head data already exists

**Converged in:** platform-retention review and interface (room) review, independently, both pinning the same dead call site.

`getHeadToHead()` / `formatHeadToHeadLabel()` in `profile.js:74` are fully implemented and unit-tested (`profile.test.js`) — and **called from zero `.jsx` files.** The single highest-attention moment on the platform (you just beat this specific person again) has the data sitting right next to it, unused. Both reviews independently rank this as the cheapest, highest-leverage motivation fix available: ~15–20 lines wiring `GameStatus.jsx`'s finished/match-over branches to data and functions that already exist, zero new Firebase writes.

The same "built once, shown nowhere" pattern repeats at the platform level: Daily Challenge's streak/best score is `localStorage`-only (never synced, so it's a different number on a different device — the exact trust gap already fixed once for match stats via F-32, silently regressed for the daily); the friends leaderboard is a one-shot pull with no delta ("you moved up two spots this week"); `WinEffect.jsx` scales confetti by round-vs-match but not by score margin, so a 3-0 sweep and a 3-2 nailbiter get identical treatment despite the data existing to distinguish them.

### Theme 4 — Color is used as the only signal, in several unrelated places

**Converged in:** correctness (strategy), design (arcade), interface (a11y), and interface (social) — four independent reviews, each finding a different instance of the same pattern.

- Reversi, Hex, Connect Four family, Gomoku, Order & Chaos: player pieces distinguished by disc/stone color only, no glyph (Tic Tac Toe, Ultimate TTT, and SOS correctly use X/O/S letters).
- Pong's grow/shrink/slow power-ups differ by background tint only, no shape/icon.
- Friend presence dots (`InviteFriendModal.jsx:72`, and repeated in `PlayerCard.jsx:39-46`, `WaitingRoom.jsx`) — online/offline conveyed by a bare color-changing dot, no icon or text fallback.
- Mono theme collapses `--c-p1`, `--c-cta`, and `--c-win` to near-identical values (p1==cta exactly; win 1.05:1 off) — in that theme specifically, any UI relying on those three tokens as *distinct* signals loses the distinction entirely.

No single reviewer was asked to hunt for this across the whole app — it surfaced four times because it's a real, repeated pattern, not a per-game oversight. The interface (a11y) review notes explicitly: **no colorblind-simulation pass has evidently been run**, which is consistent with the pattern recurring rather than being caught once and repeated.

## 6. What to add

Missing features, ranked by how much each would change a player's actual experience. Drawn from the platform, party, and solo design reviews' "what is missing" sections.

1. **Surface the head-to-head record on the win screen.** (Theme 3.) Trivial effort, the highest-leverage single change in this document — the data and functions already exist and are tested.
2. **Sync Daily Challenge and give it a real payoff loop.** Mirror `{best, streak}` to `users/{uid}/daily/{date}` (the exact pattern `mirrorStats` already established for match stats); rotate the featured game daily instead of always Mental Math, doubling as catalog exposure for the other 46 games. Medium effort.
3. **Rank the leaderboard per game, with a time window.** (Theme 2.) The data (`stats.byGame`) already exists; this is reshaping an existing read, no new Firebase rules. Medium effort.
4. **Persist each game's own best metric, not just win/loss.** `users/{uid}/pb/{gameType}: { value, achievedAt }` — best Chimp level, fastest reaction time, highest WPM×accuracy, etc. Currently a player can plateau at Chimp level 6 forever and their stats look identical to a player who's climbed to level 15, as long as opponents are similarly matched. This is the one concrete fix that moves all nine "parallel-instance" score-producing games' Motivation at once. Low-medium effort (one Firebase node + one UI banner per game, no logic change).
5. **Give the friends list an asynchronous reason to check it.** Every social touchpoint today is synchronous/session-bound (invites only fire live, the leaderboard is a one-shot pull). One signal — a friend finished a match, your rank changed — surfaced as a badge/toast on next open, not live-only. Before building: check whether the actual friend graph has enough edge density to make this non-empty for a typical user (unmeasured — flagged as a prerequisite, not a build order).
6. **Add a per-friend match history / rivalry log.** A `matches/{uid}/{matchId}` append-log at the same point `recordMatch` already fires would retroactively power a real head-to-head view, a leaderboard time window, and an activity feed — one new write, no new architecture.
7. **A spy-guesses-the-location active win condition for Spyfair.** Currently the spy only wins passively by surviving the vote; adding a `spyGuess(locationIndex)` action (gated behind a minimum elapsed time so it isn't a free early guess) gives the spy real agency, matching the genre convention.
8. **A bot opponent for Bluff Battle**, even a simple EV-threshold bidder, so the game is practiceable solo before a player's first exposure is a live human.
9. **An n-player mode for Two Truths**, or an honest recategorization as a 2-player icebreaker rather than a party game — see the per-game verdict.
10. **Shuffle Fibbage's prompt order** (a per-match seed, matching every sibling deck-driven game) — independent of and cheaper than growing the 26-prompt deck, and removes the "bot's lie is predictable on a schedule" compounding effect.
11. **Grow the Fibbage (→100+) and Trivia (→200+) content decks** — both decks' own header comments already state these as the target; this restates the team's own stated goal with a measured current gap (26 prompts / 6 matches to first repeat, respectively).
12. **Overlap-cancellation scoring for Word Hunt** — classic 2-player Boggle's fix for "both players credit the same common short word" (an unsourced starting rule, not a citable text, per the reviewing design pass — worth a measured check post-ship).

## 8. Consolidator's observations

One cross-cutting pattern noticed while merging these thirteen reports that no single source review stated explicitly, offered separately per the instruction not to blend new findings into the consolidated record above:

**Word Duel is the single most bug-dense game in the entire review set, across four independent review lenses that never cross-referenced each other.** The correctness review found its `GameSwitcher` prop bug (already fixed per the prior UX audit, but originally discovered there). The mobile-UX audit found it completely unplayable on touch (§2 #1, this document's #1 fix). The party-design review flagged its dictionary as containing crude words a setter could deliberately select. The interface reviews didn't single it out further only because the other three already had. No individual finding here is new — the pattern of one game accumulating independent hits from every review angle is. Worth a dedicated close-out pass on this one file (`WordDuelGame.jsx` + `wordduelLogic.js`) rather than fixing each finding in isolation as it's triaged, since a game that's drawn this many independent hits across unrelated review lenses may have more waiting under a live/rendered check than any of the thirteen reports could see from source alone.
