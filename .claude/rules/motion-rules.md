# Motion Rules

- **Two grammars, one rule.** What a finger or the system moves (sheets, pages, presses, drags) uses springs that keep velocity when interrupted. What the game announces (pieces, stamps, banners, loaders, sprites) may use the pixel `steps()` grammar. Never step something under the finger: it reads as lag.
- **Tokens, not literals.** Durations `--dur-press` 80 / `--dur-fast` 150 / `--dur-base` 220 / `--dur-page` 300 ms; curves `--ease-standard` / `--ease-enter` / `--ease-exit` (Material 3); springs `--spring-ui`, `--spring-pop`, `--spring-press`, `--spring-page` as CSS `linear()` with a matching `-dur`. Tailwind exposes them as `duration-press|fast|base|page` and `ease-standard|enter|exit|spring-ui|spring-pop`; plain `transition` already uses the standard curve. JS uses `src/lib/motion.js` (`DUR`, `EASE`, `springPreset`) and, from lazily loaded code only, `src/lib/spring.js` (`animateSpring` and the gesture helpers) so the entry bundle stays small. Changing a spring preset means regenerating its CSS curve: `motion.test.js` fails until `index.css` matches `springLinear()`.
- **Per platform.** Presets are picked by `motionPlatform()` (iOS / Android inside the Capacitor shell, web otherwise); CSS follows `html[data-native]`. iOS values are SwiftUI's springs, Android's are Material 3 spring tokens.
- **Transition named properties.** Use `transition` (colour, opacity, shadow, transform, filter), `transition-colors` or `transition-transform` — never `transition-all`, which tweens layout and half-animates a theme switch. When a width or height genuinely animates, name it: `transition-[width]`. Animate `transform` and `opacity`; a progress bar scales (`scaleX`), it does not change `width`.
- **Presses.** Controls use `press` (scale 0.96), cards and rows `press-card` (0.98): an 80 ms press-in, a minimum visible dip, a spring release (`src/lib/pressFeedback.js`, loaded after the entry). No other `active:scale-*` values.
- **Overlays.** Every modal goes through `BottomSheet` (`centered` for a dialog; the implementation is the lazily loaded `BottomSheetPanel.jsx`): spring in, exit on every close path, backdrop tied to the panel. Do not hand-roll `fixed inset-0` modals.
- **Page and theme changes.** Navigation goes through `MotionRouter` (View Transitions; the kind comes from `lib/routeTransitionLogic.js`, CSS under `html[data-route-vt]`), so pages need no per-route animation. A player's theme pick uses `pickTheme()` (`lib/theme.js`, which loads `switchTheme()` from `lib/themeSwitch.js` on demand), not `applyTheme()`.
- **Reduced motion is calmer, not nothing.** CSS animations are frozen app-wide by `[data-motion="reduced"]` and the OS query; any extra `@media (prefers-reduced-motion: reduce)` rule must be scoped `:root:not([data-motion="full"])` so the in-app FULL setting wins. JS checks `isReducedMotion()` (`hooks/useMotionPref.js`) and swaps movement for a 150 ms crossfade; smooth scrolling goes through `scrollBehavior()` (same file).
- **Feedback on contact.** Haptics and sounds fire when the thing lands or the finger touches, never after a network acknowledgement.
- **Every animation name needs a keyframe.** `src/lib/keyframes.test.js` fails on a name with no `@keyframes` rule.
